# 热点板块模块设计思想

## 核心理念：主线的力量

A 股是一个**板块效应极强**的市场。个股涨跌的 60%+ 可以由所属板块解释。
看懂板块轮动，就能看懂 A 股。

```
不是"涨了才知道是热点"，而是"识别主线信号，提前站在水流方向"。
```

## 数据采集：三层爬虫架构

### 为什么用三层？

| 层 | 技术 | 速度 | 稳定性 | 使用场景 |
|----|------|------|--------|----------|
| Playwright | 真实浏览器 + JS XHR | 慢（3-5s 启动） | 最高（浏览器指纹） | 主数据源，反反爬 |
| Requests + Headers | `requests.Session()` | 快 | 中（简单 UA 伪装） | 自动降级 |
| AkShare 库 | 封装 HTTP | 快 | 低（纯 API 调用） | 兜底 |

**真实浏览器方案的设计理由：**

东方财富的 push2.eastmoney.com API 是最丰富的 A 股实时数据源，但有反爬机制。用真实浏览器（Playwright）模拟用户访问：
1. 携带真实 Cookie 和 Session
2. 通过 `page.evaluate()` 在浏览器上下文中执行 XHR（同源策略允许）
3. 注入反检测脚本（隐藏 `navigator.webdriver`）
4. 随机 UA + Viewport 降低识别概率

**不是简单 requests + headers**，因为 push2 接口在检测到非浏览器环境时可能返回空数据或触发验证。Playwright 方案虽然慢一点，但数据完整度远高于纯 HTTP 方案。

```
Playwright 浏览器启动
    ↓
访问 quote.eastmoney.com (建立 Session/Cookie)
    ↓
page.evaluate(XMLHttpRequest) → push2 API
    ↓
JSONP 解析 ({data: {diff: [...]}})
    ↓
失败 → 回退到 requests + Cookie 直连
```

## 热点评分系统

### 七维度评分体系（方法论增强版）

评分 = 基础四维度 + 方法论增强三维度

#### 基础四维度（原有）

```python
base_score = sector_change × 2        # 板块当日涨幅
           + limit_up_count × 5       # 涨停家数（板块内）
           + ladder_completeness × 8  # 连板梯队完整度
           + leader_correlation × 15  # 龙头带动效应
```

| 维度 | 权重 | 为什么 |
|------|------|--------|
| 龙头带动效应 | ×15 最高 | 有龙头的板块才有持续性。没龙头的板块是一盘散沙 |
| 连板梯队 | ×8 | 梯队越完整（1 板→2 板→3 板），资金参与度越高 |
| 涨停家数 | ×5 | 板块内涨停股票越多，资金共识越强 |
| 板块涨幅 | ×2 | 基础信号，但单独看容易受一两只权重股影响 |

**为什么板块涨幅权重最低？** 因为"板块涨 3%"可能只是其中一只权重股（如茅台拉白酒）导致的，不代表整个板块有持续性。涨停家数和龙头效应才是核心。

#### 方法论增强三维度（2026.06 新增）

```python
sentiment_multiplier = _build_market_context()  # 全市场情绪乘数 0.70~1.30
topic_level_score    = _calc_topic_level(name)   # 题材级别得分 5/10/15
resonance_score      = _calc_index_resonance()   # 指数共振得分 0~15

final_score = base_score × sentiment_multiplier + topic_level_score + resonance_score
```

**① 情绪乘数（sentiment_multiplier）— 北京炒家+涅盘重升**

全市场的"水温"决定了板块分数的实际含金量：

| 全市场涨停家数 | 情绪乘数 | 含义 |
|---------------|---------|------|
| ≥ 80 只 | ×1.30 | 极度活跃，溢价放大 |
| ≥ 50 只 | ×1.15 | 活跃市场，适度放大 |
| ≥ 30 只 | ×1.00 | 正常市场，不调整 |
| ≥ 15 只 | ×0.85 | 低迷市场，分数打折 |
| < 15 只 | ×0.70 | 冰点市场，谨慎对待 |

> 引自北京炒家："大势所致，不是图形好不好、或者主不主流的问题"。同样的板块强度在牛市和熊市意义完全不同。

数据来源：`akshare.get_market_profit_effect()` 的全市场涨停家数。

**② 题材级别（topic_level）— 陈小群**

题材的"级别"决定了行情的高度和持续性：

| 级别 | 加分 | 典型关键词 | 持续预期 |
|------|------|-----------|---------|
| **国家级** | +15 | 新能源、芯片、AI、军工、碳中和、国企改革、低空经济 | 数周至数月行情 |
| **行业级** | +10 | 涨价、消费、医药、汽车、有色、金融、通信 | 数日至数周行情 |
| **个股消息** | +5 | 不匹配以上关键词，常为个股利好驱动 | 一日游居多 |

> 引自陈小群："很多人买了龙头但没赚到钱，因为对题材级别能涨多高多久的理解不够"。国家级题材可以走出翻倍龙头，行业级题材只能做阶段性行情。

实现方式：板块名称关键词匹配（`TOPIC_LEVEL_KEYWORDS` 字典），涵盖 60+ A 股常见概念板块关键词。

**③ 指数共振（index_resonance）— 北京炒家**

判断板块是否"强于指数"——只有比市场平均更强的板块才值得关注：

| 跑赢前排均值 | 得分 | 含义 |
|------------|------|------|
| > 3% | 15 | 显著强于市场，资金集中攻击 |
| > 2% | 12 | 明显强于市场 |
| > 1% | 8 | 略强于市场 |
| > 0.5% | 5 | 微弱优势 |
| > 0% | 3 | 勉强跑赢 |
| ≤ 0% | 0 | 弱于市场，回避 |

> 引自北京炒家："要强，只有强才能带来超预期机会"。计算方式：板块涨幅 vs 当日 Top 10 板块的平均涨幅。

### 龙头识别

```python
1. 获取板块成分股
2. 筛选涨停股 → 按连板天数降序
3. 连板天数最多 = 潜在龙头
4. 计算筹码质量评分（四维度0-100）:
   - 浮筹清洗度(30分): 近期缩量+窄幅震荡 → 筹码干净
   - 稳定性(25分): 近期波动率低 → 持股信心强
   - 爆炒风险(25分): 近60日涨幅小 → 无套牢盘
   - 趋势结构(20分): 均线多头排列 → 筹码锁定好
5. 综合排序: 连板天数 × 0.5 + 筹码评分 × 0.05
6. 验证: 龙头涨跌幅与板块其他股涨跌幅的 Spearman 相关系数 > 0.3
   → 有带动效应，龙头身份确认
   → 否则只是独立走势，不被视为龙头
```

**为什么需要相关性验证？** 有时一只股票连续涨停但板块内其他股票不跟涨——这种情况属于"妖股"而非"龙头"。龙头必须能带动板块。采用 Spearman 秩相关而非 Pearson，因为涨停/跌停的极端值对 Pearson 影响过大。

### 题材生命周期分类（92科比框架）

基于单日数据实时判断板块所处的生命周期阶段：

| 分类 | 判断条件 | 含义 |
|------|---------|------|
| **主升期** | 连板≥5 + 涨停≥5 + 龙头相关系数>0.3，或连板≥3 + 涨停≥8 | 龙头清晰、板块批量涨停，任何位置进都是对的 |
| **强势轮动** | 连板≥3 | 有龙头但板块宽度不够，适合做龙头分歧低吸 |
| **低位试错** | 连板≥1 + 涨停≥3 | 题材初现、龙头未明，适合打首板或做补涨 |
| **脉冲** | 龙头相关系数<0.2 或涨停<3 | 一日游行情，参与价值低 |
| **未知** | 无连板数据 | 暂无方向判断 |

> 引自 92科比："题材的内容不是最重要的，题材出现的时机才是重点"。同一板块在"主升期"和"高位震荡期"的操作策略完全不同。

### 连板梯队检测

有两种实现方式，选择取决于对速度还是精度的要求：

| 方式 | 方法 | 速度 | 精度 |
|------|------|------|------|
| K 线回查 | 逐只股票查 30 天日线，数涨停天数 | 慢（N 只 × 1 API 调用） | 精确 |
| 爬虫增强 | 一次接口获取涨停池 + 连板数据 | 快（1 次 API 调用） | 部分数据缺失 |

**实际采用**：默认 K 线回查（保证精度），当 `BoardScraperFetcher` 可用时自动切换为爬虫增强模式（~200 倍加速）。

## 多源数据汇聚

### 七大热点维度

除了基础的板块排行，热点分析还汇聚 7 个维度的数据：

| 维度 | 数据源 | 用途 |
|------|--------|------|
| 概念板块排行 | AkShare / EmHidden | 发现情绪驱动的流派行情 |
| 热门个股排行 | AkShare / EmHidden | 资金攻击的方向标 |
| 涨停板池 | AkShare / BoardScraper | 打板情绪温度计 |
| 概念资金流 | AkShare / EmHidden | 聪明钱流入/流出方向 |
| 行业资金流 | AkShare / EmHidden | 主力资金的行业偏好 |
| 北向资金 | AkShare / EmHidden | 外资态度 |
| 市场赚钱效应 | AkShare / EmHidden | 整体情绪冷暖 |

**设计理念：单一数据源不可信。** 如果板块涨了但资金在流出 → 警惕一日游。如果北向在加仓 + 板块在涨 + 涨停家数增加 → 确认主线。

## 板块轮动跟踪（持续性分类）

### 为什么需要多日跟踪？

单日板块排行是噪音。真正的"主线板块"必须经过时间检验：

```
单日第一 → 可能是一日游消息刺激
连续 3 天前 10 → 资金持续关注
连续 5 天前 5 → 主线确认
```

### 分类系统

```python
分类维度:
  持续性(consecutive): 连续几天进入排行榜
  频率(appearance):    过去 N 天出现比例
  趋势(trend):         评分的时间序列斜率

输出 6 种分类:
  🔥 主线     → 持续≥5天 + 频率≥60%
  🚀 强势轮动 → 持续≥3天 + 频率≥40% + 趋势向上
  🔄 轮动     → 频率≥30%
  ⚡ 脉冲     → ≤2天 + 低频 (一日游)
  🆕 异动     → 刚出现 + 趋势向上 (观察)
  📉 退潮     → 趋势显著向下 (回避)
```

### 指标计算

| 指标 | 方法 |
|------|------|
| 持续性 | 从最新交易日倒推，相邻记录间隔 ≤3 天算连续 |
| 频率 | `出现天数 / 总交易日` |
| 趋势斜率 | 评分的 `np.polyfit` 线性回归斜率，归一化到 -10~+10 |
| 5 日动量 | `最新评分 - 5 天前评分` |
| 排名波动 | `np.std(排名数组)`，波动小代表稳定性强 |

## 缓存与预热

### 三层缓存架构

```
Layer 1: 板快成分股缓存 (SectorCacheService)
  - SQLite 表 board_members_cache
  - TTL: 24h
  - 策略: stale-while-revalidate (过期可读, 后台更新)

Layer 2: 热点分析持久化 (SectorAnalysisStorage)
  - SQLite 表 sector_analysis
  - 保留: 14 天
  - 用途: 预计算结果 + 历史回溯

Layer 3: 爬虫快照 (BoardScraperStorage)
  - SQLite 表 board_scraper_log 等
  - 保留: 14 天
  - 用途: 原始爬虫数据缓存
```

### 预热机制

```
服务启动后 30 秒:
  → 获取 Top 20 板块排行
  → 对 Top 10 板块获取成分股
  → 写入 SectorCacheService
  → 下次请求直接读缓存
```

**设计理由**：板块分析最慢的部分是首次请求——既没缓存又没预计算。预热确保第一个用户访问时数据已在缓存中。

## 数据处理：失败无关原则

```
数据采集   → 失败 → 记录错误，继续下一个
评分计算   → 失败 → 跳过该板块，不影响其他板块
结果存储   → 失败 → 日志告警，不阻塞主流程
API 返回   → 无数据 → 返回空列表 + cache_status=empty
```

**每个数据源都是可选的。** 即使 Playwright 不可用、AkShare 限流、甚至全部数据源都失败，系统不会 500——会返回提示信息给用户。

## API 设计

```
GET  /hot?market=cn&limit=20          ← 主查询接口
GET  /rankings?market=cn              ← 快速排行
POST /trigger-analysis                 ← 强迫症/手动触发
POST /parse-manual                     ← 人工复盘录入
POST /trigger-scraper                  ← 手动爬虫
GET  /scraper-board-data              ← 原始爬虫数据
GET  /available-dates                  ← 历史数据日期
GET  /scraper-available-dates          ← 爬虫数据日期
```

**为什么 GET /hot 既返回预计算又支持实时回退？** 预计算是最可靠的（收盘后算好），但有时用户开盘后就想看或预计算尚未运行。实时回退作为保底方案，保证任何时候都有数据。

## 设计原则总结

| 原则 | 代码中的体现 | 方法论来源 |
|------|-------------|-----------|
| **主线 > 脉冲** | 持续性×频率 + 龙头验证，避免追一日游 | 通用 |
| **数据源分层降级** | Playwright → Requests → AkShare，单层失败不阻断 | — |
| **缓存尽早预热** | 30s 后台预热 + stale-while-revalidate + 14 天持久化 | — |
| **实时 + 预计算双保险** | GET /hot 先查预计算，没有再实时分析 | — |
| **龙头验证** | 必须通过 Spearman 相关性验证，不是涨停就算 | 陈小群 |
| **多维度交叉验证** | 涨幅 + 涨停 + 资金流 + 北向，多个维度同时印证 | 通用 |
| **速度 vs 精度** | K 线回查(精确) vs 爬虫增强(快速)，自动选择 | — |
| **大势判断 > 个股图形** | 情绪乘数根据全市场涨停家数动态调整评分 | 北京炒家、涅盘重升 |
| **题材级别决定持续性** | 国家级(+15) / 行业级(+10) / 个股消息(+5) 加权 | 陈小群 |
| **强于指数才有参与价值** | 指数共振评分，跑赢前排平均越多分越高 | 北京炒家 |
| **题材出现时机 > 内容** | 生命周期分类：主升/强势轮动/低位试错/脉冲 | 92科比 |
| **筹码质量决定龙头高度** | 四维筹码评分(浮筹清洗+稳定性+爆炒风险+趋势) | 北京炒家 |

## 附录：方法论溯源

2026-06 增强基于《新生代游资热点方法论》五位顶级游资的交易哲学：

| 游资 | 贡献维度 | 核心语录 | 代码位置 |
|------|---------|---------|---------|
| **北京炒家** | 情绪乘数、指数共振、筹码质量、形态过滤 | "要强，只有强才能带来超预期机会" | `_build_market_context()`, `_calc_index_resonance()`, `_score_chip_quality()` |
| **陈小群** | 题材级别判断、龙头合力验证 | "很多人买了龙头但没赚到钱，因为对题材级别能涨多高多久的理解不够" | `TOPIC_LEVEL_KEYWORDS`, `_calc_topic_level()`, `_calc_leader_correlation()` |
| **92科比** | 生命周期四阶段、补涨时机、龙头四大特征 | "题材的内容不是最重要的，题材出现的时机才是重点" | `_classify_sector_lifecycle()`, `_identify_leader()` |
| **涅盘重升** | 水温判断、低吸确定性的时机 | "当以前这种位置你进去都能吃肉，现在总是吃面时，这个时候就要小心" | `_build_market_context()` 情绪判断 |
| **一瞬流光** | 满仓三大条件、龙头渡劫 | "永远只看龙头，少看杂毛弱转强，这是大面源泉" | `_identify_leader()` 龙头优先策略 |
