# 信号链「明日买入」标的 · 筹码体检 设计方案

**日期**: 2026-09-11
**目标**: 从信号链筛出「今日回踩完成→明日买入」的股票，一键对其跑本地筹码体检，用买入语义识别诱多/派发陷阱，作为明日买入前的二次确认。

---

## 1. 背景与问题

### 1.1 现有两个功能

| 功能 | 位置 | 产出 |
|------|------|------|
| 信号链 | `apps/dsa-web/src/pages/SignalPipelinePage.tsx` + `api/v1/endpoints/signal_pipeline.py` + 仓库外 `~/stockData/dsa_signal/screen_signal.py` | 多时段 MRMC 状态机，`信号状态` 含一档 `今日回踩完成→明日买入`（突破 SA 后回踩触及 SB 且当日收阳） |
| 筹码体检 | `apps/dsa-web/src/pages/ChipHealthPage.tsx` + `api/v1/endpoints/chip_health.py` + `src/services/chip_health_service.py` | 本地 3 年日线筹码引擎，输入 `code/name/cost` 临时清单，输出 🔴/🟠/🟡/⚪/🟢 减仓判定 |

### 1.2 衔接动机

技术信号给出"明日买入"，但底部筹码若正连日流失（主力派发），该买点大概率是诱多。用筹码引擎给这批候选票做二次过滤。

### 1.3 关键前置事实（已实测）

**日线信号链当前从不产出 `今日回踩完成→明日买入`**：`screen_daily` 状态机在触发当日执行 `signal_idx=-1` 复位，早于循环后"出信号块"（`if signal_idx >= 0`），导致出信号块里该分支为死代码。实测近 8 个交易日日线该状态计数全为 0；分钟时段（5/15/30min）正常产出（走 `min_state`，在触发处记录 `last_status`）。

本方案**先修复日线状态机**，再以日线候选为体检输入（"明日买入"本质是日线级决策）。

---

## 2. 边界与决策

| 决策点 | 选定 |
|--------|------|
| 候选时段 | 修复日线后取日线 `今日回踩完成→明日买入` |
| 入口 | 信号链页就地按钮（非新建页、非体检页导入） |
| 判定文案 | 买入语义转译（纯前端文案层，底层引擎数值不变） |
| 实现变体 | 前端编排：复用现有 `chip /run`（临时清单）与 `/results`，**DSA 仓零新增后端端点** |

**仓库边界**：日线修复文件 `screen_signal.py` 位于 `~/stockData/dsa_signal/`，在本 git 仓库之外，信号链 API 以 subprocess 调它。该修复不纳入本仓 PR，单独执行并说明验证方式。

---

## 3. 数据流

```
运行管线(修复后) → GET /signal-pipeline/results?date&timeframe=daily
   → 前端 pickBuyTomorrow(rows)  [过滤 信号状态==='今日回踩完成→明日买入']
   → 组 holdings [{code,name,cost:null}]
   → POST /chip-health/run (临时清单，300s 超时)
   → 引擎输出 🔴/🟠/🟡/⚪/🟢 + profit/bottom/loss3/5/7
   → 前端 buyVerdict(level, high_profit_risk) 买入语义转译
   → Modal/展开区表格展示
```

---

## 4. 组件设计

### 4.1 日线状态机修复（仓库外 `screen_signal.py::screen_daily`）

- 现状缺陷：触发日复位丢失状态（见 1.3）。
- 修复口径：仿 `min_state`，当 `breakout and low[i] <= sb[i] and close[i] > open_[i]` 且 `i == n-1`（今日触发）时，记录状态 `今日回踩完成→明日买入`，信号日期取原始 `dates[signal_idx]`（复位前），随后复位。
- 非今日触发：维持现状丢弃（该回踩已在更早完成，非"明日"信号）。
- 精确改动：仅补触发当日捕获，不重构其余分支，不动分钟逻辑。

### 4.2 后端（DSA 仓）

- **无新增端点**。复用：
  - `GET /api/v1/signal-pipeline/results`（`api/v1/endpoints/signal_pipeline.py`）——修复+重跑后自动带出日线回踩完成行。
  - `POST /api/v1/chip-health/run`（`api/v1/endpoints/chip_health.py` + `chip_health_service.run_check`）——接收临时 `holdings`，不覆盖已保存持仓；cost 为空照常计算 profit/bottom/loss。

### 4.3 前端（DSA 仓 `apps/dsa-web`）

**`src/api/signalPipeline.ts` 新增导出纯函数：**
- `pickBuyTomorrow(rows: SignalRow[]): HoldingItem[]`
  - 过滤 `row['信号状态'] === '今日回踩完成→明日买入'`
  - 映射 `{ code: 股票代码.padStart(6,'0'), name: 股票名称, cost: null }`

**买入文案转译纯函数 `buyVerdict(level, highProfitRisk)`：**

| 引擎档位 | 买入语义 |
|---------|----------|
| 🟢 | 技术+筹码双确认 · 可买 |
| ⚪ | 量化做T假象 · 可正常买 |
| 🟡 | 筹码不稳 · 轻仓/观察 |
| 🟠 | 底筹连降 · 诱多风险，谨慎 |
| 🔴 | 主力派发 · 放弃明日买入 |
| — | 数据不足 · 无法判断 |

- `highProfitRisk===true` 时追加 `⚠️获利盘>90%`。
- 档位底色/边框复用 `ChipHealthPage` 的 `LEVEL_META` 语义。

**`SignalPipelinePage.tsx`：**
- 仅日线 tab 生效。`const buyList = pickBuyTomorrow(results.rows)`。
- `buyList.length > 0` 时结果表上方出横幅：「🎯 {N} 只明日买入标的 · 一键筹码体检」+ 按钮。
- 点击 → `chipHealthApi.run(buyList)` → 打开结果 **Modal**（复用 `components/common` 现有弹层原语，无则新建轻量 Modal）渲染结果表，列：判定(买入语义) / 代码·名称 / 收盘 / 获利比例 / 底筹 / 流失3·5·7日 / 结论。
- 0 标的时横幅隐藏，不报错。
- 沿用 `chipHealthApi.run` 现有 `timeout: 300000`。

## 5. 错误处理

| 场景 | 行为 |
|------|------|
| 引擎缓存缺失（未跑收盘管线） | `run` 返回 400，横幅下方红字提示"先跑收盘流水线" |
| 体检超时/子进程失败 | 现有 500 映射，前端 catch 显示 detail |
| 日线无回踩完成标的 | 横幅隐藏（多数交易日正常状态，非错误） |
| 候选中个别票缓存太短 | 引擎 `skipped[]` 返回，表尾列"跳过 N 只" |

单点失败不阻断信号链主视图（体检是增量动作）。

## 8. 风险点

- **语义**：分钟时段仍产出同名标签；本功能只读日线，避免混淆。
- **依赖外部脚本**：日线体检的可用性取决于 `screen_signal.py` 修复 + 管线重跑，属仓外资产，需在交付说明中标注验证状态。
- **成本字段**：候选未持仓，cost 置空，体检不显示浮盈（正常，非缺陷）。
