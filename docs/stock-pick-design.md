# 选股模块设计原理与判断逻辑

> 完整设计文档，覆盖 7 步选股流水线的每一个模块：判断逻辑、核心公式、阈值选择、设计取舍。

---

## 总框架：自上而下的战场地图

选股不是"翻石头"，而是**读地图 → 选战区 → 找据点**。

```
宏观       板块       基本面     技术面     仓位       风控       执行
  ↓         ↓         ↓         ↓         ↓         ↓         ↓
 ①市场状态  ②板块锁定  ③基本面扫描  ④个股精选  ⑤仓位计算  ⑥止损评估  ⑦调仓信号
```

每一层输出都是下一层的输入。方向错了，再精密的计算也是白费。

## ① 市场状态分类 — "今天该不该打"

### 模块

`src/core/market_regime.py` → `MarketRegimeClassifier`

### 核心问题

绝大多数亏损不是因为选错了股，而是**在错误的时间做了错误的决策**。牛市什么策略都好用，熊市什么策略都容易亏。在市场不可操作的时间段，最好的操作就是空仓。

### 方法论：五维规则引擎

不是 ML。ML 需要大量标注数据且解释性差。规则引擎基于经典技术指标，输出确定的阶段标签和仓位系数。金融领域，**可解释性 > 黑盒精度**。

```
输入: 上证综指 / 深证成指 / 创业板指 日线 (120天)
            ↓
    ┌───────┼───────┬───────┬───────┐
    ↓       ↓       ↓       ↓       ↓
  趋势    量能    宽度    波动率   情绪
 (35%)   (20%)   (20%)   (10%)   (15%)
    ↓       ↓       ↓       ↓       ↓
    └───────┼───────┴───────┴───────┘
            ↓
      综合加权 → 7 种市场阶段
```

### 维度详解

| 维度 | 指标 | 权重 | 计算逻辑 | 选择理由 |
|------|------|:----:|----------|----------|
| **趋势** | MA5/10/20/60 排列 | 35% | 多头MA排列→高分，空头排列→低分；MA60斜率印证 | 技术分析最基础、最稳定的信号 |
| **量能** | 5日/20日均量比 | 20% | vol_ratio>1.2=放量，<0.8=缩量 | 量是价的先行指标，无量不攻 |
| **宽度** | 涨跌家数比 | 20% | 涨/(涨+跌)比例，>60%=宽度良好 | 确认趋势的广度，避免指数失真 |
| **波动率** | ATR 比值 | 10% | 近期ATR/长期ATR，<1.0=低波动蓄势 | 高波动→减仓，低波动→趋势可能启动 |
| **情绪** | 涨停/跌停家数 | 15% | 跌停>涨停→恐慌，涨停>>跌停→亢奋 | A股特有的情绪指标，极端值反转概率高 |

### 7 阶段分类逻辑

```
信号组合判断 (signals: trend + sentiment):

1. bull_trend (主升趋势)
   trend=trending_up + sentiment=calm
   → 仓位系数: 0.70~0.95
   → 建议: 进攻为主，仓位≤90%

2. bull_consolidation (震荡上行)
   trend=trending_up + 量能不足
   → 仓位系数: 0.50~0.80
   → 建议: 均衡偏进攻，仓位≤60%

3. range_bound (区间震荡)
   无明确方向
   → 仓位系数: 0.40~0.60
   → 建议: 高抛低吸，仓位≤50%

4. bear_consolidation (震荡下行)
   trend=trending_down + 宽度尚可
   → 仓位系数: 0.25~0.45
   → 建议: 防御为主，仓位≤30%

5. bear_trend (主跌趋势)
   trend=trending_down + sentiment=pessimistic
   → 仓位系数: 0.10~0.30
   → 建议: 空仓或极轻仓，仓位≤15%

6. bottom_reversal (底部反转)
   sentiment=extreme_fear + breadth开始改善
   → 仓位系数: 0.30~0.50
   → 建议: 试探性建仓，仓位≤40%

7. extreme_sentiment (极端情绪)
   sentiment=extreme_greed 或 extreme_fear
   → 仓位系数: 根据方向 0.10~0.90
   → 建议: 恐惧时贪婪，贪婪时恐惧
```

### 置信度与仓位系数

```
composite_score = Σ(dimension_score[i] × weight[i])
confidence = clamp(composite_score, 0, 100)

# 仓位系数在阶段范围内插值
factor = lo + (composite_score / 100.0) × (hi - lo)
```

### 为什么趋势权重最高（35%）？

A 股在统计上是强趋势市场（动量效应显著），趋势一旦形成，持续性远高于美股。在一个趋势驱动的市场里，顺势而为比任何选股技巧都重要。

## ② 板块锁定 — "水流向哪里，鱼就在哪里"

### 模块

`src/services/sector_rotation_tracker.py` → `SectorRotationTracker`

### 核心问题

A 股是板块轮动驱动的市场。每天有几十个板块涨跌，大部分是一日游。**能把"主线"和"脉冲"区分开的人，就已经赢了 90% 的选股者。**

前一天涨得最好的板块，次日有显著的均值回归倾向。持续性维度是对抗回归的第一道防线。

### 三维分类体系

```
核心识别维度:
  持续性(consecutive_days)  : 连续几天出现在排行榜前 N
  频率(appearance_ratio)    : 过去 N 个交易日出现比例
  趋势(score_trend)         : 评分的时间序列斜率

分类输出:
  🔥 主线      — 连续≥5天 + 频率≥60%     → 重点参与
  🚀 强势轮动  — 连续≥3天 + 频率≥40%     → 观察确认
  🔄 轮动      — 频率≥30%                 → 正常参与
  ⚡ 脉冲      — ≤2天 + 低频              → 不追
  🆕 异动      — 刚出现 + 趋势向上        → 标记观察
  📉 退潮      — 趋势显著为负             → 回避
```

### 分类阈值

```python
CLASSIFICATION_RULES = {
    "main_line":       {"consecutive": 5, "appearance_ratio": 0.6},   # 主线
    "strong_rotating": {"consecutive": 3, "appearance_ratio": 0.4},   # 强势轮动
    "rotating":        {"appearance_ratio": 0.3},                      # 轮动
    "pulse":           {"max_consecutive": 2},                         # 脉冲
    "emerging":        {"conditions": "recent_only"},                  # 异动
    "fading":          {"conditions": "trend_negative"},               # 退潮
}
```

### 评估顺序

1. **持续性优先** — 连续天数是最强信号（regression-resistant）
2. **频率印证** — 高频出现确认信号强度
3. **趋势方向** — score_trend 为正→上升板块，为负→衰减板块

### 输出

除了完整排行，额外输出三组分类列表：

- `top_main_lines`: 主线板块（最值得参与）
- `rising_sectors`: 上升板块（潜在主线候选）
- `fading_sectors`: 退潮板块（应回避）

### 数据来源

| 数据 | 来源 | 说明 |
|------|------|------|
| 板块排行 | `sector_analysis_storage` (BoardScraper 历史) | 多日排行榜 |
| 板块成分股 | `board_scraper_fetcher` (东财 push2 API) | 成分股列表+涨跌幅 |

## ③ 基本面扫描 — "先看财务底牌，再看技术形态"

### 模块

`src/services/fundamental_screener.py` → `FundamentalScreener`

### 核心问题

技术面能告诉你"什么时候买"，但只有基本面能告诉你"值不值得买"。财报季前后，业绩驱动是股价最核心的发动机。过滤掉基本面有问题的股票，技术分析才有意义。

### 数据来源

**AkShare `stock_yjbb_em`**（东方财富业绩报表）— 单次 API 调用获取全市场 ~5000+ 只股票的核心财务指标。

### 三层漏斗

```
全市场股票 (~5000+)
    ↓
条件①: 营收同比增长 > 20%  → 剔除衰退公司
    ↓
条件②: 净利润同比增长 > 50%  → 选出高成长公司
    ↓
条件③: 净利润 > 5000万    → 剔除微利/亏损公司
    ↓
Top 50 候选 (综合评分排序)
```

### 阈值选择

| 条件 | 阈值 | 理由 |
|------|:---:|------|
| 营收增长 | >20% | P0 门槛：营收不增长的公司大概率在萎缩 |
| 利润增长 | >50% | 核心筛选：高增长是牛股的前提 |
| 净利润绝对值 | >0.5亿 | 安全网：排除"增长率高但基数低"的误导 |

### 综合评分

```python
score = 营收档位分 + 利润档位分 + 净利润档位分

营收层级: ≥50% → 3分, ≥30% → 2分, ≥20% → 1分
利润层级: ≥100% → 5分, ≥70% → 3分, ≥50% → 1分
净利润层级: ≥5亿 → 2分, ≥0.5亿 → 1分

总分范围: 2~10
```

### 设计取舍

**只做三维度而不用更多指标**：ROE、毛利率、现金流等也很好，但 AkShare 的 `stock_yjbb_em` 接口的核心字段有限。营收+利润+净利润能覆盖"成长性"的核心维度，且数据覆盖率最高（缺失率低）。

**为什么用同比而不是环比？** 财报有明显季节性（如四季度集中结算），同比消除季节性噪声，提供更干净的增速信号。

## ④ 个股精选 — "漏斗比满仓更重要"

### 模块

`src/services/stock_screener_service.py` → `StockScreenerService`

### 核心问题

一个板块 50~200 只股票，人类的注意力只能同时处理 3~5 个。**选股不是找"所有好股票"，而是从 N 只中快速筛出最值得深度分析的那几只。**

### 四层漏斗架构

```
板块成分股 (50-200)
    ↓
L1: 流动性筛选  ── 成交额>阈值, 换手率>阈值   (全量通过，延迟日线调用)
    ↓  裁剪至30只（保留涨幅最大的）
L2: 趋势确认    ── MA多头排列, 价格>MA20       (逐股获取日线，Tushare调用)
    ↓
L3: 板块内排名  ── N日涨幅排序, 保留前30%       (相对强度排序)
    ↓
L4: 综合评分    ── 六因子加权评分               (精细排序)
    ↓
Top 3-10 候选
```

### L1 流动性筛选

| 条件 | 默认阈值 | 目的 |
|------|:---:|------|
| 日均成交额 | >1亿 | 过滤仙股、僵尸股 |
| 换手率 | >1% | 确保有足够流动性 |

> **设计决策**：L1 全量通过不调日线 API。仅用实时行情数据（价格、涨跌幅、成交额），速度快。日线调用延迟到 L2（仅对裁剪后的 30 只股票调用 Tushare），规避 Tushare 50次/分钟的限速。

### L2 趋势确认

逐股获取日线数据（Tushare P-1 → Efinance P0 → AkShare P1），验证：
- MA5 > MA10 > MA20（多头排列）
- 最新收盘价 > MA20（价格在中期均线上方）

### L3 板块内排名

按 N 日涨幅排序，保留前 30%（`top_n_ratio=0.3`）。

```python
# RS = 个股涨幅 / 板块平均涨幅
rs = stock_change_pct / avg_sector_change_pct
survivors = sorted(survivors, key=lambda s: s["change_pct"], reverse=True)[:int(len(survivors) * top_n_ratio)]
```

### L4 六因子综合评分

| 因子 | 权重 | 意义 | 计算方式 |
|------|:---:|------|----------|
| **趋势强度** | 25% | MA 排列质量 | MA5>MA10=+15,MA10>MA20=+15,MA20斜率+15,价格>MA20=+5, 基础50 |
| **相对强度 RS** | 25% | 个股 vs 板块 | RS=2.0→100, RS=0.5→30, 线性映射 |
| **量能确认** | 15% | 近期量 vs 长期量 | ratio=5日均量/20日均量 → ratio>1.3→70+, ratio<0.7→30- |
| **乖离率** | 10% | 距离 MA5 的距离 | <3%=优(80+), 3-5%=中等(60+), 5-8%=偏高(40+), >8%=危险(<40) |
| **涨停距离** | 10% | 距涨停板的距离 | <5%=追涨风险高, >20%=安全 |
| **龙头评分** | 15% | 板块内领涨地位 | 涨幅前3=80, 前10=65, 前20=50, 其余=40 |

> **设计原则**：不去预测"明天会不会涨"，而是判断"这只股票比板块内其他股票好在哪里"。RS（相对强度）是最核心的信号——强势的股票倾向于继续强势（动量效应）。

### 为什么用多因子而不是 ML？

1. **可解释性**：每个分值得分都能追溯到具体的市场现象（MA排列、量能比等）
2. **样本量**：单板块 <200 只，不足以训练有意义的 ML 模型
3. **数据质量**：因子可以容忍部分字段缺失，ML 不行
4. **调参直觉**：权重调整有金融逻辑支撑，不是梯度下降的黑盒

## ⑤ 仓位计算 — "决定胜负的不是买没买，而是买了多少"

### 模块

`src/services/position_sizer.py` → `PositionSizer`

### 核心问题

**90% 的散户亏钱不是因为选错股，而是选对股但仓位太低，选错股但仓位太高。** 职业交易员的优势不在选股，在仓位管理。

### 三层约束体系

```
推荐仓位 = min(
    Kelly公式:  f* = (p × R - q) / R       ← 长期复利最优
    风控约束:  单笔亏损 ≤ 账户×2%           ← 生存优先
    市场约束:  仓位 ≤ regime_factor×25%     ← 顺势而为
)
```

### 计算流程

```python
# 1. 单股风险
risk_per_share = |entry_price - stop_loss_price|

# 2. 风控约束 (Risk-of-Ruin Protection)
max_risk_amount = account_equity × 2%
risk_adjusted_shares = max_risk_amount / risk_per_share

# 3. 市场阶段调整
regime_budget = account_equity × market_regime_factor × 25%

# 4. Kelly 公式
win_prob = signal_confidence / 100
kelly = (win_prob × target_rr - (1 - win_prob)) / target_rr
kelly = clamp(kelly, 0, 0.25)  # 上限 25%

# 5. 最终推荐 (按置信度分级)
if confidence >= 70% and regime >= 0.70: → 全Kelly
elif confidence >= 60%:                   → 半Kelly (50%)
else:                                     → 半仓×风控约束
```

### 为什么用半 Kelly？

全 Kelly 的波动性极高（可能在最优路径上回撤 70%+）。半 Kelly 在保持约 75% 增长效率的同时，将最大回撤降低约 50%。

### 约束层次

| 约束 | 目的 | 防什么 |
|------|------|--------|
| Kelly | 长期复利最优 | 仓位过小浪费机会 |
| 风险预算 2% | 连续 50 次全错不破产 | 单笔过热 |
| 市场阶段系数 | 牛市重仓，熊市轻仓 | 逆势操作 |
| 板块上限 40% | 分散化 | 板块集中风险 |
| 单股上限 25% | 集中度控制 | 单股黑天鹅 |

## ⑥ 止损管理 — "买入之前就想好怎么输"

### 模块

`src/services/stop_loss_manager.py` → `StopLossManager`

### 核心问题

**散户最常见的死法：不止损 → 深套 → 被迫变成长期股东 → 底部割肉。** 这不是投资，这是赌博。

### 三层止损体系

```
入场前确定:
  Layer 1: 硬止损 — ATR/MA/结构低点 → 确定的出场价
  Layer 2: 移动止损 — 价格上涨 → 止损上移（保护利润）
  Layer 3: 时间止损 — 20日未验证逻辑 → 退出

每笔交易前定义:
  R = |入场价 - 止损价| × 股数
  每笔 R ≤ 账户总资金的 2%
  目标盈亏比: R:R ≥ 1:2
```

### 止损锚点计算

```python
# ATR止损 (默认, 趋势交易首选)
ATR = 14日平均真实波幅
hard_stop = entry_price - ATR × 2.0

# MA止损 (上升趋势备选)
MA20 = 20日收盘均价
hard_stop = MA20  # 收盘跌破MA20即止损
trailing_start = entry_price × 1.05  # 涨5%后启动移动止损

# 结构止损 (有明确支撑位时)
hard_stop = 60日最低价  # 不破波段低点

# 百分比兜底 (无数据时)
hard_stop = entry_price × (1 - 4%)  # 默认4%硬止损
```

### 三层止损触发逻辑

```
硬止损:  current_price ≤ hard_stop → 无条件退出
移动止损: price涨至trailing_start → 止损价=最新高价-ATR×2.0
时间止损: entry_date + 20天 → 仍未盈利 → 退出
```

### 移动止损的"利润保护"逻辑

```python
# 价格每创阶段新高，止损线上移
highest_price = max(highest_price, current_price)
trailing_stop = highest_price - ATR × 2.0

# 举例: 100买入, ATR=5
#   → 硬止损=90
#   → 涨到110 → 移动止损=100 (即保本)
#   → 涨到120 → 移动止损=110 (锁定10%利润)
#   → 跌回110 → 触发止损, 盈利10%离场
```

### 止损锚点选择

| 锚点 | 适用场景 | 优势 | 劣势 |
|------|----------|------|------|
| ATR × 2 | 趋势交易 | 自适应波动，不会太紧太松 | 对横盘震荡不敏感 |
| MA20 | 上升趋势 | 简单明确，顺势持有 | 急涨后可能被扫 |
| 波段低点 | 结构交易 | 明确的支撑/阻力 | 需要手动识别，量化难 |

**组合使用**：入场用 ATR 止损，趋势形成后用 MA20 移动止损。

## ⑦ 调仓信号 — "去弱留强，不跟股票谈恋爱"

### 模块

`src/services/rebalance_engine.py` → `RebalanceEngine`

### 核心问题

**最大亏损永远来自"曾经赚钱最终亏钱"。** 散户的典型错误：赚 5% 跑掉 → 涨到 50% → 后悔 → 高位追回 → 跌 30% → 死扛。

### RS 排名 + 事件驱动

```
定时(每周):
  按 RS(个股涨幅/板块涨幅) 排列所有持仓
  Top 50% → 持有/加仓
  Bottom 20% → 减仓/清仓

事件驱动(随时):
  止损触发 → 立即清仓
  龙头切换 → 卖跟风, 买新龙头
```

### 六大交易信号

| 信号 | 触发条件 | 操作 |
|------|----------|------|
| **BUY** | RS在板块top 10% + 市场bull | 新开仓 |
| **ADD** | 持仓在top 30% + 趋势增强 | 加仓 |
| **HOLD** | 持仓在30%-70%区间 | 持有不动 |
| **REDUCE** | 持仓在bottom 30% + 趋势减弱 | 减仓50% |
| **EXIT** | 持仓在bottom 20% + RS显著走弱 | 全部清仓 |
| **ROTATE** | 持仓在bottom 30% + 同板块有新龙头 | 卖出换入龙头 |

### 信号生成阈值

```python
hold_threshold_pct = 0.5     # 持有线: top 50%
weak_threshold_pct = 0.2     # 弱势线: bottom 20%
leader_rs_threshold = 1.3    # 龙头RS阈值: RS > 1.3 为龙头
max_sector_positions = 3     # 单板块最多持仓数
```

### 为什么用 RS 而不是 PnL？

亏损的股票可能只是正常的回调（趋势未破），但 RS 低的股票说明它**相比板块在走弱**——这才是真正的卖出信号。PnL 反映的是过去，RS 反映的是"相对强弱"这个当前的竞争状态。

## 设计原则

| 原则 | 含义 | 代码体现 |
|------|------|----------|
| **Top-Down** | 宏观→板块→基本面→个股 | ①→②→③→④ 每层输出驱动下一层 |
| **Best-Effort** | 数据拿不到也要能工作 | 所有外部调用都有 try/except + 默认值 |
| **可解释性 > 黑盒** | 每个分数都能解释 | 六因子评分，每因子独立可回溯 |
| **生存优先** | 先不亏再谈赚 | 仓位 2% 风险上限 + 三层止损 |
| **截断亏损，让利润奔跑** | 卖出差的，持有好的 | RS 排名 + 去弱留强 |
| **流程可验证** | 每步独立可运行 | 每步有 CLI 入口和 API 端点 |
